# Snipe-IT: учёт IT-оборудования и лицензий

Runbook по развёртыванию Snipe-IT — open-source системы учёта IT-активов (ноутбуки, мониторы, лицензии на ПО) — в Docker на Ubuntu Server.

## Стек

- Ubuntu Server 24.04, Docker, Docker Compose
- Snipe-IT (образ `snipe/snipe-it`)
- MariaDB 10.11
- Redis (кэш и сессии)

## Схема

```
Браузер администратора
        │  http://<IP_сервера>:8080
        ▼
   Контейнер snipe-it (Laravel)
        │                    │
        ▼                    ▼
   MariaDB (db)          Redis (кэш, сессии)
```

## Шаг 3. Файл переменных (.env)

В `.env` хранятся все пароли и настройки, поэтому сам файл в репозиторий не кладётся — в проекте лежит только шаблон [`.env.example`](.env.example). Скопируй его и заполни:

```bash
cp .env.example .env
```

`APP_KEY` нужен Laravel для шифрования данных (сессии, пароли и т.п.). Сгенерировать:

```bash
echo "base64:$(openssl rand -base64 32)"
```

Результат вставь в `APP_KEY` в `.env`. Там же задай:

- `APP_URL` — адрес сервера с портом (`http://<IP_сервера>:8080`)
- `DB_PASSWORD`, `DB_ROOT_PASSWORD` — пароли для MariaDB (должны совпадать с тем, что укажешь в `docker-compose.yml`/переменных окружения на шаге 4)

SMTP (отправку писем) на этом этапе можно не настраивать, по умолчанию стоит `MAIL_DRIVER=log` — письма просто пишутся в лог вместо отправки.

## Шаг 4. docker-compose.yml

Файл [`docker-compose.yml`](docker-compose.yml) поднимает три контейнера: сам Snipe-IT, MariaDB и Redis. Пароли для базы данных контейнер `db` читает из тех же переменных, что и `.env` (`DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`, `DB_ROOT_PASSWORD`), поэтому отдельно их задавать не нужно — достаточно один раз заполнить `.env`.

Три тома обеспечивают сохранность данных между перезапусками контейнеров:

| Том | Что хранит |
|---|---|
| `snipeit_data` | загруженные файлы, изображения, ключи приложения |
| `db_data` | саму базу данных — без него при пересоздании контейнера база потеряется |
| `redis_data` | кэш и сессии |

## Шаг 6. Первоначальная настройка в веб-интерфейсе

Открой `http://<IP_сервера>:8080` — откроется мастер создания учётной записи администратора.

| Поле | Что вписать |
|---|---|
| Название сайта | название компании/отдела вместо стандартного «Snipe-IT Asset Management» |
| Имя и Фамилия | свои данные вместо примера |
| Электронная почта | свой рабочий email — важно стереть плейсхолдер `${MAIL_ENV_FROM_ADDR}`, он подставился из-за ненастроенного SMTP |
| Имя пользователя | логин для входа |
| Пароль | надёжный пароль администратора |
| «Отправить мои учётные данные…» | оставить пустым: SMTP не настроен, письмо не уйдёт |
| Префикс | опционально, например `IT-` или `PC-`, если планируешь клеить штрихкоды на технику |
| Длина инвентарного номера | 5 — хватает до 99 999 устройств |
| Генерировать метки активов автоувеличением | рекомендуется включить: система сама предложит следующий номер (`IT-00001`, `IT-00002` и т.д.) |
| Полная поддержка нескольких компаний | не включать, если вся техника числится за одним юрлицом |
| Язык по умолчанию | Русский |
| Валюта по умолчанию | сменить `USD` на `RUB` (или свою валюту), иначе стоимость техники будет считаться неверно |

## Шаг 7. Траблшутинг

**`docker compose up -d` падает с ошибкой `failed to resolve reference "docker.io/snipe/snipe-it:latest"` / `network is unreachable`.**
Docker не может достучаться до Docker Hub напрямую. Решение — прописать зеркала реестра.

1. Создай или отредактируй `/etc/docker/daemon.json`, взяв за основу [`daemon.json.example`](daemon.json.example):

   ```bash
   sudo cp daemon.json.example /etc/docker/daemon.json
   sudo nano /etc/docker/daemon.json   # если файл уже был не пустым — дополнить, не затереть
   ```

2. Перезапусти Docker и повтори запуск:

   ```bash
   sudo systemctl restart docker
   docker compose up -d
   ```

Конкретные зеркала могут со временем переставать работать или появляться новые — если ни одно из списка не отвечает, стоит поискать актуальный список зеркал.

## Что можно улучшить

- **Redis без пароля** (`REDIS_PASSWORD=null`). Для сервера, доступного только изнутри сети, это приемлемо, но для продакшена стоит задать пароль и прописать его в `.env`.
- **SMTP не настроен.** Пока `MAIL_DRIVER=log`, уведомления (о новых пользователях, истечении лицензий и т.д.) никуда не уходят, их видно только в логах контейнера.
- **Порт 8080 торчит наружу без reverse proxy и HTTPS.** По аналогии с Vaultwarden-проектом стоит повесить Snipe-IT за Nginx Proxy Manager с локальным сертификатом и ограничить доступ через UFW.
- **Резервное копирование тома `db_data`.** Сейчас это единственное место, где хранится вся база учёта оборудования — без бэкапа её потеря необратима.
